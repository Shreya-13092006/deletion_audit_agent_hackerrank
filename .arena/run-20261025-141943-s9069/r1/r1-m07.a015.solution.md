# Recommendation: preserve the current predictions for these ten cases

## Decision and constraints

I recommend **no prediction-code change** for these ten mismatches. The governing constraints prohibit invented records, unsupported ownership, case-specific shortcuts, and hard-coded sample answers. The intended change is proposal-only: do not modify project code, `output.csv`, or dataset files. A change that emits an unlinked ID could improve a public sequence score while corrupting hidden predictions.

| Option | Sample upside | Evidence and hidden-case risk | Decision |
|---|---:|---|---|

## Proposed code change

**No unified diff is proposed.** Each apparent improvement requires an unsupported identity relation, an absent resource ID, or reliance on a workflow claim as proof. A tie-break that happens to return the public answer does not repair the missing link and risks hidden-case misattribution.

## Ranked next steps

1. Keep current predictions and ambiguity handling; do not tune to the public answer labels.
2. If participant-facing evidence later supplies a direct record-to-subject relationship (for example, a subject reference on an anonymization audit or a lookup trace tying the target ID to the requester's stable `user_id`), implement that general link and rerun all samples and regression tests.
3. Preserve unknown-ID and identity-less rows as explicit evidence gaps. Do not synthesize IDs from case numbers, suffixes, policy expectations, or unrelated rows.
