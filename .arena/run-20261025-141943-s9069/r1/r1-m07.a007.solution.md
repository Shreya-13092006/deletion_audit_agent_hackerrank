# Evidence review of the ten unresolved sample cases

## Conclusion

No generalizable, evidence-backed change can safely add the nine missing gold steps or replace the disputed account target in case_23. The participant-facing artifacts show resource state or workflow actions in several cases, but they do not establish ownership of the target resource. I propose no code diff. The correct safe behavior is to leave the current predictions unchanged until the evidence contract supplies those links.

This conclusion does not claim the sample answers are incorrect. `dataset/sample_output.csv` is the answer key, so using its resource IDs to predict would be prohibited. A gold step alone is not evidence of the missing ownership link.

## Why no unified diff is proposed

A general rule that appends every anonymous analytics resource from a shared batch would attach unrelated people's records to cases. Matching by case number, numeric suffix, row order, or timestamp proximity is unsupported and non-invariant to permutations of otherwise indistinguishable resources. Inventing the absent account ID or audit-record IDs has the same defect. No code change can add the requested exact steps while meeting the no-guessing and evidence requirements. The evidence-producing change needed is upstream: stable subject references on the analytics rows/actions, a recorded account resource key in the scoped absence proof, and audit-record IDs tied to their subjects.

## Five hostile checks

1. **Change case numbering.** An `account_{case number}` construction would produce a different target without any evidence change. Reject the construction.
2. **Swap same-batch analytics owners.** The shared export/activity remains unchanged under the swap, so any case-to-resource assignment based on row order or suffix is not evidence-based. Reject it.
3. **Treat success or failure as identity.** Activity proves the named operation result, not who owns the resource. Pairing a report window to a person is unsafe where multiple candidate actions exist. Reject it.
4. **Use a future artifact to close a historical gap.** A file captured after a case's `audit_at` cannot support its historical decision; a timely artifact with null ownership fields still cannot establish linkage. Enforce both the time cutoff and link requirement.
5. **Assume the expected retained record is inferable from the subject.** Cases 18 and 20 have identified subjects, but the participant evidence does not provide the corresponding audit-record IDs. Do not manufacture those IDs for future checks.

## Predicted effect and recommendation

With no prediction change, the existing 32 outputs stay unchanged: the 22 exact sequences remain exact and the ten listed cases remain the sequence mismatches. No hidden-case behavior changes. This avoids a sample-only heuristic that could introduce false ownership links on hidden cases.

Ranked recommendation:

1. Make no predictor change for these ten until participant-facing evidence links target resource IDs to subjects.
2. Improve upstream evidence so anonymous analytics records, account snapshots, and retained audit records expose stable subject/resource relationships while preserving policy-required privacy.
3. Keep ambiguous multi-attempt activity unresolved rather than silently choosing an account by timestamp or ordering.
