# Recommendation: keep the ten cases unresolved

## Decision

No code change is warranted for these ten gaps. The participant-facing evidence establishes some requested resources and current resource shapes, but it does not establish the missing resource IDs or prove ownership of several already-anonymized analytics rows. Adding those gold steps would require using the answer key or guessing a link. That would violate the evidence and generalization requirements for hidden cases.

I concede the prior write-up did not make its negative searches reproducible at row level. I corrected that weakness here with the exact search scope, commands, zero-match results, and the positive row references. This is an evidence/reporting correction only; there is no implementation diff.

## Proposed change and predicted effect

**No code change.** A missing record ID cannot be derived from an empty exact-ID search; an identifier-free analytics record cannot be assigned to a person without a remaining linkage; and the failed account rows do not associate the three resources to the three deletion requests. No unified diff is proposed. A rule based on sample IDs, activity timing, record order, or similar metrics would memorize labels or guess ownership and could create false findings on hidden cases.

With no code or prediction change, predicted sample effects are: status accuracy unchanged; step/evidence results unchanged; 22 of 32 exact sequences remain exact; the same ten cases remain the known sequence mismatches. The 22 existing matches are preserved, and there are no predicted effects on hidden cases because no behavior changes. This trades potential public-label sequence gains for avoiding unsupported resource attribution.

## Ranked recommendation

1. Keep conservative behavior for these cases until participant-facing linkage evidence exists. This preserves evidence discipline and the current 22 exact sample sequences, at the cost of leaving ten public sequence mismatches.
2. Improve evidence generation for future cases: preserve a subject-to-resource audit cross-reference that remains available to the auditor while direct identifiers are removed from analytics content; expose the retained security-record ID tied to a stable subject reference; and record lookup results for account resources with a reliable requester link.
3. If new participant-facing evidence is supplied, rerun all 32 public samples and the regression suite before changing the engine. Do not use public gold answers as prediction features.
