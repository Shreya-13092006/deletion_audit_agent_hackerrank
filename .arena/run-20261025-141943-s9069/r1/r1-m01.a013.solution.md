# Recommendation: leave the ten labels unresolved in code

## Assumptions

I treat the public sample answers only as the evaluator comparator, never as an input for prediction rules. “Improve” means improve accuracy and defensibility on hidden cases, not force exact sample matches by correlating on timing or copying expected IDs. Activity rows and reported workflow statuses remain claims under AGENTS.md §6.5–6.6.

## Result

No evidence-backed code change can produce the ten missing gold steps from the supplied participant-facing data. Nine require a verification resource whose ownership cannot be linked to the requester. The tenth (`case_23`) has multiple indistinguishable account candidates. The current output is correct on status and every shared step.

The sample run evaluated at status accuracy 1.000, step precision/recall/F1 0.995/0.948/0.971, evidence accuracy 1.000, and sequence accuracy 22/32. All ten listed cases remain the sequence mismatches. The full suite passed 192 tests after redirecting `TMP` and `TEMP` to the permitted scratch directory; the first run failed because the default Windows temporary directory was sandboxed.

## Recommendation

1. Do not hard-code or infer the missing identifiers. Preserve the current evidence-backed output and expose ambiguity for review.
2. If exact sample matching is required, repair the input contract upstream by adding participant-visible subject-to-resource links and point-in-time state evidence, or revise gold steps that cannot be derived from supplied inputs. Then rerun the sample evaluator and the 192-test suite.
3. Keep account ties reviewable. Resolve them only when the evidence adds a subject link; do not choose by case numbering, event order or answer-derived lookup.

## Regression impact

No project code change is proposed, so the predicted effect is unchanged on all 32 public samples: the same 22 remain exact matches, the same ten mismatches remain, and status/step/evidence metrics remain as reported above. This preserves all 22 existing exact matches and avoids introducing unsupported behavior on the 518 hidden cases.
