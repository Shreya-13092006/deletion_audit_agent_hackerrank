# Review of the ten unresolved public sample cases

## Conclusion and proposed change

No code change is supportable from participant-facing evidence. The mismatches are either an unsupported resource-to-person assignment or a resource ID with no participant-facing occurrence. The safe proposal is a unified diff with no changes. The linker must continue to require an explicit identity/resource link; the state resolver must continue to distinguish state evidence from ownership evidence; and the planner must emit checks only for established resources. Guessing from case numbers, batch order, timestamps, workflow claims, or the sample answer would violate the evidence and no-shortcut rules.

## Predicted effect and regression scope

The proposed diff is empty, so the predicted output on all 32 public cases is unchanged: statuses remain 32/32 correct, the same 22 sequences remain exact, and these same ten disagreements remain. All 22 existing exact matches are untouched, so the proposal predicts no regressions among them. This is a prediction from the stated unchanged implementation, not a newly measured rerun.

## Ranked recommendation

1. Keep the current conservative outputs; do not add the unsupported IDs or infer their owners.
2. For case_23 and the anonymous analytics records, change the result only if new participant-facing evidence supplies a direct identity/resource link valid at that case's audit_at.
3. For case_04, case_18, and case_20, first require participant-facing evidence that actually contains the asserted resource ID and scopes its absence/presence. Then add a general parser/state rule and regression examples based on that evidence.
