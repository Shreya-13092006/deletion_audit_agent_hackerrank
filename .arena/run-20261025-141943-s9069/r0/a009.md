# Decision: there is no compliant, generalizable patch for the ten residual mismatches

## Open questions and assumptions

1. Does “improve” require changing code, or is a checkable no-change conclusion acceptable? The task explicitly permits a proof that a case cannot be improved without inventing IDs or ownership. I use that option where the evidence cannot resolve attribution.
2. Can workflow time or neighboring records identify the owner of an identifier-free resource? Only if evidence distinguishes one requester. A shared batch/window is not a per-person link; I do not treat closeness, ordering, totals, cohort, or an unqualified success status as ownership.
3. May the public answer file guide predictions? No. I used it only to locate the discrepancies and compare output; it is not evidence for rules or IDs.
4. Are later files usable for an earlier audit? No. Evidence after a case's audit_at cannot prove its state then.

## Expert review and edge-case decision

**Evidence/identity reviewer:** a resource needs a participant-visible identity link, a uniquely attributable workflow, or a scoped record relation. Names and approximate timing alone are unsafe. In particular, a batch containing records for several deletion requests does not tell us which anonymous analytics profile belongs to which requester.

**Pipeline reviewer:** the planner already emits policy verification only for resources it discovered and tied to the subject. Adding an unconditional retained-record or analytics verification would be unsound: the planner would have no grounded ResourceState, ownership, or evidence. A generic “every retained type” rule would also create false steps for unrelated users and could cite no evidence.

**Evaluation reviewer:** a sample-specific branch or memorized ID could raise sequence accuracy on the public set while violating §6.7 and harming the hidden set. We therefore settle on no patch for these ten. The useful improvement is to make the boundary reproducible and preserve the current 22 exact matches.

Filtering on cohort, record order, or action time is likewise non-unique and not a stable rule for the 518-case set. No compliant diff.

## Exact proposed change

There is no unified diff to apply. In particular, do not add any of the ten IDs to a rule, alias map, exception table, or case branch. That would turn sample answer knowledge into predictions, not improve evidence resolution.

## Predicted effect and regression status

With no code changes, expected sample results are exactly the reproduced baseline: the same 22 exact matches remain exact; the same ten remain unresolved; statuses and cited evidence remain unchanged. Therefore this does not claim a sequence-score gain. It avoids sacrificing the 22 correct sequences or emitting unsupported records across the 518 hidden cases. A concrete effect of any hypothetical heuristic cannot honestly be promised as “no regressions” without running and inspecting its output; the candidate heuristics above have a direct counterexample: multiple indistinguishable batch members / account claimants.

I also ran the requested unittest command using the available bundled Python runtime. In this restricted Windows environment, 26 tests errored when tempfile attempted writes under the protected AppData temp location; 147 tests completed. These are sandbox PermissionErrors, not test assertion failures, so this run does not establish a clean full-suite pass. The repository review file docs/reviews/evaluation-2026-10-25.md separately records the prior successful 170-test run and independent checks; I do not represent that prior run as mine.

## Ranked recommendation

1. Keep the current evidence/ownership gate; do not force these ten IDs into the output.
2. If the data contract can be amended, add participant-facing owner links or subject-scoped workflow metadata for these records and regenerate the public gold consistently. That would permit a general attribution rule rather than a sample exception.
3. Add a regression check that each emitted resource has a traceable identifier, scoped link, or uniquely attributable workflow; keep the existing 22 exact cases as the no-regression baseline.
