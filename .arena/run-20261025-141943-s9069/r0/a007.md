# The 10 sample gaps: no safe prediction change is supported

## Decision

The baseline's conclusion is mostly right, but its proof is too compressed to audit: “searched everywhere” and “chance” are not reproducible findings. I checked the actual sample run, the visible activity and evidence references for the disputed IDs, and the matching cases' times and identities. I find **no rule change that can produce the ten gold steps without adding an ownership/ID guess**. I recommend leaving the predictor and its sample output unchanged. There is no honest unified diff to offer.

That is not the same as saying the gold answers are wrong: the gold may use hidden ground truth. It means the participant-facing artifacts provided here do not establish those specific resource-to-person links. Filling them from `sample_output.csv` would violate the stated no-answer-memorization rule.

## Five hostile checks

1. **Sequential account IDs:** change a case number or imagine the next account ID differs from the case number. Any `account_{case number}` rule breaks immediately; the snapshot does not establish that convention. Reject it.
2. **Swap two anonymized analytics rows within the same batch.** Every visible identifier, workflow time, and shared-file citation remains the same. Any content/order mapping that selects one owner is not invariant to this swap. Reject it.
3. **Treat a success event as ownership.** The activity records say an operation succeeded on a resource, not who it belongs to. Pairing by a report-time window can attach it to another case in that window. Reject it.
4. **Use a tempting numeric coincidence.** Case IDs, analytics IDs, audit-record suffixes, and neighboring resource numbers are independent labels. No common identifier or documented generator rule connects them. Reject suffix arithmetic and ordering.
5. **Let later evidence fill an earlier gap.** `evidence_94` was captured after case_04’s audit cutoff; it cannot repair that case. Even when a file is before cutoff, null identifiers remain null. Apply the cutoff and fail closed on the unresolved link.

These attacks leave the baseline's “no exact fix” result intact. I also ran the full unit command using the bundled Python: 173 tests were discovered, with 26 errors caused by sandbox `PermissionError` when tests attempted writes/cleanup in Windows' external `Temp` directory. The remaining tests ran; this is an environment failure, not evidence that a proposed code change passes the suite. Since I propose no code change, I make no regression-pass claim.

## Predicted effect and ranked recommendation

There is no proposed prediction change. All 32 sample rows therefore remain as in the reproduced run: the current 22 exact matches remain exact; these 10 remain the only sequence mismatches. This preserves current hidden-case behavior and avoids introducing an unvalidated ownership heuristic.

1. **For these ten, do not patch the prediction logic.** Exact matching would require new participant-visible ownership or resource-ID evidence.
2. **Improve the evidence contract at its source.** Future evidence should include a stable subject reference on each anonymous analytics action/readback, the account resource ID in the scoped absence record, and retained audit IDs tied to their subject. This would make the desired checks derivable without using labels from the answer key.
3. **Keep the ambiguous workflow cases surfaced for review.** In particular, do not silently resolve account candidates by event-time proximity when several failed deletes fit one request window. That may improve safety on hidden cases, but it cannot justify substituting `account_410` for `account_9155` from this evidence set.

## Assumptions

- `sample_output.csv` is an evaluation reference, not permitted prediction evidence, as the task explicitly says.
- A workflow event establishes that the named resource was acted on; it does not by itself establish the resource's owner.
- A shared snapshot or log file containing multiple owners is not a record-level ownership link unless its row or trace connects the disputed resource to the subject.
